# PRODUCT_SENSE.md — 제품 방향성과 철학

AI 에이전트가 기능 구현 판단을 내릴 때 이 문서를 기준으로 삼습니다.
"이걸 만들어야 하나?" 라는 질문에 대한 답이 여기에 있습니다.

---

## 1. 우리가 해결하는 문제

취업 준비생이 회사 하나를 조사하려면:

- 회사 홈페이지, 잡플래닛, 블라인드, 링크드인, 기술 블로그, 채용 공고, 뉴스를 각각 찾아다녀야 함
- 정보가 분산되어 있고 신뢰도도 제각각
- 회사 하나 분석하는 데 수 시간 소요
- 여러 회사를 비교하려면 그 시간이 배가 됨

**우리가 제공하는 것**: 회사명 하나로 위 과정을 5분 안에 끝내는 경험

---

## 2. 타겟 유저

### Primary — 취업 준비생

| 구분 | 특징 |
|------|------|
| 신입 개발자 | 회사 문화, 기술 스택, 복지가 가장 중요 |
| 주니어 개발자 | 성장 가능성, 연봉, 팀 분위기 비교 필요 |
| 이직 준비자 | 현재 회사와 목표 회사 비교, 재무 안정성 확인 |

### Secondary — 현직자

- 자신이 다니는 회사에 대한 리뷰 작성
- 타 회사 동향 파악

---

## 3. 핵심 가치 (Core Values)

### V1. 정확성보다 투명성
수치가 불확실하면 "정보 없음"으로 표시. 틀린 정보를 자신있게 말하지 않는다.
→ DART 공시 수치는 출처 있을 때만 인용, LLM 추측 수치는 제공하지 않음

### V2. 속도보다 신뢰
답변이 느려도 괜찮다. 틀린 답변이 빠른 것보다 낫다.
→ 크롤링/DART 조회가 느려도 정확한 데이터 우선

### V3. 복잡함보다 단순함
사용자가 URL을 입력하거나 설명할 필요 없이 **회사명 하나**로 모든 게 시작된다.
→ 인텐트 분류로 사용자 의도를 자동 파악

### V4. 정보 통합
여러 소스(홈페이지, DART, 뉴스, 직원 리뷰)를 한 곳에서 종합하는 것이 핵심 차별점.
→ 단순 검색이 아닌 멀티소스 RAG 파이프라인

## 4. 핵심 기능 (현재 구현 기준)

| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 회사 정보 수집 | 회사 웹사이트 크롤링 + DART 공시 자동 조회 | P0 |
| 자연어 Q&A | "카카오 복지 어때?" 같은 자연어 질문 처리 | P0 |
| 심층 분석 리포트 | 7개 섹션 구조화된 기업 분석 자동 생성 | P1 |
| 회사 비교 | 두 회사 이상 항목별 비교 테이블 생성 | P1 |
| 직원 리뷰 | 사용자가 직접 리뷰 작성 및 분석 | P2 |
| 최신 뉴스 | 네이버 뉴스 API 연동 최신 동향 제공 | P2 |

---

## 5. 하지 않는 것 (Anti-goals)

- **채용 플랫폼 대체**: 실제 채용 공고 지원 기능은 제공하지 않음
- **SNS 기능**: 리뷰 좋아요/댓글/팔로우 등 소셜 기능 없음
- **실시간 주가/시세**: 금융 데이터 실시간 연동 없음
- **회사 광고/홍보**: 특정 회사에 유리한 정보 편향 없음

---

## 6. 성공 기준

| 지표 | 목표 |
|------|------|
| 회사 정보 수집 완료까지 | 3분 이내 |
| 질문 응답 생성 시간 | 10초 이내 |
| 심층 분석 리포트 생성 | 30초 이내 |
| 사용자가 "정보가 부족하다"고 느끼는 비율 | 20% 미만 |

---

## 7. 제품 결정 기준

기능 추가/변경을 결정할 때 이 질문들로 판단:

1. **취업 준비생의 회사 조사 시간을 줄여주는가?**
2. **제공하는 정보가 신뢰할 수 있는 출처에서 오는가?**
3. **단순하고 직관적으로 사용할 수 있는가?**
4. **세 가지 모두 "예"가 아니면 만들지 않는다.**
