# DESIGN.md — 단일 대화형 UI 원칙

이 문서는 현재 제품을 "모드 없는 대화형 어시스턴트"로 유지하기 위한 UI/UX 기준을 정의합니다.
새로운 화면이나 컴포넌트를 추가할 때는 별도 도구 화면보다 하나의 자연스러운 대화 흐름을 우선합니다.

---

## 1. 제품 방향

### D1. 사용자는 기능 모드를 선택하지 않는다
사용자는 질문만 입력하고, 시스템이 크롤링/질문응답/비교/리서치 같은 내부 처리를 알아서 수행해야 합니다.
UI는 이를 노출하지 않고 하나의 assistant 경험으로 보여줍니다.

### D2. 기본 인터페이스는 채팅이다
핵심 경험은 채팅 화면입니다.
탐색, 설정, 회사 선택은 보조 기능이며 메인 경험을 방해하면 안 됩니다.

### D3. 복잡한 결과도 같은 말투와 같은 레이아웃 안에서 보여준다
비교표, 긴 리포트, 요약, 출처 목록은 모두 assistant 메시지의 확장 형태로 취급합니다.
특정 기능마다 완전히 다른 카드 스타일이나 화면 모드를 만들지 않습니다.

### D4. 사용자가 이해해야 하는 것은 결과이지 시스템 상태가 아니다
`qa`, `research`, `compare` 같은 내부 타입을 UI에 드러내지 않습니다.
대신 "무엇을 알게 되었는가", "어떤 근거를 썼는가"만 명확하게 보여줍니다.

### D5. 정보 신뢰도는 디자인으로 보조한다
화려한 강조보다 구조화, 여백, 출처 표시, 문장 톤으로 신뢰를 만듭니다.

---

## 2. 화면 구조

### 2-1. 전체 구조

기본 구조는 다음 두 영역으로 유지합니다.

- 사이드바: 대화 목록, 회사 선택, 보조 탐색
- 메인 영역: 현재 대화와 입력창

사이드바는 보조 수단입니다.
처음 보는 사용자는 메인 화면만 보고도 바로 질문을 시작할 수 있어야 합니다.

### 2-2. 메인 채팅 화면

채팅 화면은 세 블록으로 구성합니다.

- 상단: 현재 대화 맥락 표시
- 본문: 사용자/assistant 메시지 목록
- 하단: 고정 입력창

상단에는 시스템 모드명이 아니라 현재 선택 회사, 대화 제목, 최소한의 보조 액션만 둡니다.

---

## 3. 메시지 원칙

### 3-1. 사용자 메시지

- 오른쪽 정렬
- 짧고 명확한 버블
- 브랜드 accent 색상 사용 가능

예시 클래스:

```tsx
className="ml-auto max-w-[75%] rounded-2xl rounded-tr-sm bg-accent px-4 py-3 text-white"
```

### 3-2. Assistant 메시지

- 왼쪽 정렬
- 모든 응답 유형에 동일한 기본 컨테이너 사용
- 비교, 리서치, 요약도 같은 assistant 메시지 안에서 처리

예시 클래스:

```tsx
className="max-w-[85%] rounded-2xl rounded-tl-sm border border-[var(--color-border)]
           bg-[var(--color-card)] px-4 py-3 text-[var(--color-text)]"
```

### 3-3. 시스템 메시지

- 최소한으로만 사용
- 환영 문구, 회사 선택 안내, 오류 안내 등 짧은 문장에 한정
- assistant 답변보다 시각적 우선순위가 낮아야 함

---

## 4. 긴 응답 처리

긴 답변은 별도 모드 UI가 아니라 메시지 내부 구조로 해결합니다.

허용되는 표현:

- 제목
- 소제목
- 표
- 불릿 리스트
- 인용문
- 요약 박스

지양하는 표현:

- 기능별 전용 카드 디자인
- 비교 전용 보라 카드, 리서치 전용 파란 카드 같은 분기형 스타일
- "현재 리서치 모드" 같은 상태 배지

즉, 정보 구조는 풍부하게 하되 시각 언어는 하나로 유지합니다.

---

## 5. 출처 표시

출처는 중요하지만 본문보다 더 튀면 안 됩니다.

원칙:

- assistant 답변 하단에 배치
- 본문과 시각적으로 분리
- 링크는 새 탭으로 열기
- 출처 개수가 많아도 과도한 높이를 차지하지 않게 줄바꿈 가능한 chip 또는 리스트 사용

예시 스타일:

```tsx
className="inline-flex items-center gap-1 rounded-full border border-[var(--color-border)]
           bg-[var(--color-surface)] px-2 py-1 text-xs text-[var(--color-text-sub)]"
```

출처 표시는 "근거" 성격이어야지 "기능 태그"처럼 보이면 안 됩니다.

---

## 6. 색상 원칙

### 6-1. 기본 방향

- 다크 모드 중심 설계는 유지 가능
- 라이트 모드도 동일한 정보 구조를 유지해야 함
- 색상은 상태 구분보다 계층 구분에 사용

### 6-2. 역할

| 변수 | 용도 |
|------|------|
| `--color-bg` | 앱 전체 배경 |
| `--color-sidebar-bg` | 사이드바 배경 |
| `--color-card` | assistant 메시지, 패널 배경 |
| `--color-surface` | 입력창, 보조 패널 배경 |
| `--color-border` | 경계선 |
| `--color-text` | 본문 텍스트 |
| `--color-text-sub` | 보조 텍스트 |
| `--color-muted` | placeholder, 비활성 정보 |
| `--color-input` | 입력 필드 배경 |
| `accent` | 주요 액션, 포커스, 사용자 메시지 |

강한 색상은 CTA와 포커스 상태 정도에만 씁니다.
응답 유형별로 색을 나누지 않습니다.

---

## 7. 타이포그래피

- 기본 폰트: `"Noto Sans KR"`, `"Pretendard"`, `"Segoe UI"`, `system-ui`
- 기본 본문: 14px~15px
- 줄간격: 1.6 전후
- 긴 텍스트 읽기 편의를 우선

권장 계층:

| 용도 | 스타일 예시 |
|------|-------------|
| 페이지 제목 | `text-lg font-semibold` |
| 메시지 본문 | `text-sm leading-7` |
| 메시지 내 소제목 | `text-base font-semibold` |
| 보조 메타 정보 | `text-xs text-[var(--color-muted)]` |

---

## 8. 마크다운 렌더링

assistant 응답은 마크다운 렌더링을 기본으로 합니다.

권장 스타일:

| 요소 | 스타일 |
|------|--------|
| `h1` | `text-xl font-semibold my-3` |
| `h2` | `text-lg font-semibold my-3` |
| `h3` | `text-base font-medium my-2` |
| `p` | `leading-7 my-2` |
| `ul`, `ol` | `pl-5 my-2 space-y-1` |
| `table` | `w-full border-collapse my-4 text-sm` |
| `th`, `td` | `border border-[var(--color-border)] px-3 py-2 text-left` |
| `code` | `rounded bg-[var(--color-surface)] px-1 py-0.5 text-xs` |
| `blockquote` | `border-l-4 border-accent pl-4 text-[var(--color-text-sub)]` |

표와 섹션은 적극 활용해도 되지만, 지나치게 장식적인 배경 박스는 피합니다.

---

## 9. 입력창 원칙

입력창은 제품의 중심입니다.

원칙:

- 항상 화면 하단에 고정
- 한눈에 입력 가능해야 함
- 보조 버튼은 최소화
- placeholder는 기능 설명보다 질문 예시 중심

예시:

- `"카카오 복지 어때?"`
- `"삼성전자와 SK하이닉스 비교해줘"`
- `"네이버 심층 분석해줘"`

입력창은 "무엇을 할 수 있나"를 설명하는 대신 "무엇을 물어보면 되나"를 보여줘야 합니다.

---

## 10. 보조 UI 원칙

### 사이드바

- 대화 목록 중심
- 회사 선택, 설정 진입, 새 대화 버튼 정도만 유지
- 과도한 필터/탭/도구 메뉴는 지양

### 회사 선택

- 사용자가 회사 맥락을 지정할 수 있는 보조 기능
- 채팅 전에 반드시 거쳐야 하는 단계처럼 보이면 안 됨

### 로딩 상태

- "생각 중" 느낌의 단순한 상태 표시
- 과장된 애니메이션 대신 짧은 텍스트 또는 점 애니메이션 사용

### 오류 상태

- 기술적 에러 문구보다 다음 행동을 안내
- 예: "응답을 가져오지 못했습니다. 잠시 후 다시 시도해 주세요."

---

## 11. 접근성

- 색상만으로 상태를 구분하지 않음
- 클릭 가능한 요소는 hover, focus 상태를 명확히 제공
- 외부 링크는 `target="_blank" rel="noopener noreferrer"`
- 표, 버튼, 입력창은 키보드 사용 기준으로도 무리 없어야 함

---

## 12. 금지 사항

- 응답 타입별 전용 테마 색상 도입
- 모드 선택 탭을 메인 진입점으로 노출
- assistant 응답을 기능별 카드 묶음으로 분리
- 본문보다 더 강한 출처 강조
- 정보 구조보다 장식이 먼저 보이는 UI

이 제품은 "여러 기능을 가진 앱"처럼 보이기보다 "하나의 유능한 대화형 어시스턴트"처럼 보여야 합니다.
